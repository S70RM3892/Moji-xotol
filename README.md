# Moji-Xolotl

大学受験の英単語（共通テスト〜京大）で遊ぶ、文字タイル式の単語パズル。
袋から来る文字を1枚ずつ盤面に置き、次に来る文字に賭けながらお題の英単語を組み上げる。
見た目は壁画調。アイコンとホームの絵は `assets/xolotl.webp`。

## ルール

- 毎手、手札6枚から1枚を好きな空きマスに置く。置いた文字を含む英単語が縦か横にできれば得点。並び全体が単語である必要はない
- 1枚で複数の単語ができると**連鎖**。得点は「単語の点の合計 × 連鎖数」（上限8倍）
- 単語にならなくても置ける。その文字は**待ち**になり、あとの文字で単語の一部になれば成立する。待ちのまま終わると1枚 −15点
- 袋は「お題6語の文字 + おまけ12枚 + ★」を全部まぜたもの。手数（ふつうは34手）が尽きると残りは来ない。袋の残りは画面に出るので、来る見込みを読んで賭ける
- **手直し**（4回）で、手札を捨てるか、待ちの文字を拾って置き直せる。直前の1手はいつでも取り消せる
- **お題**は和訳と字数だけが見える。自力で作ると3倍。つづりを見ると通常の点になり、復習に回る
- ★は好きな文字になる。×2・×3マスに置いて単語を作るとその得点が倍になる
- 実在する英単語（ENABLE 収録語）なら成立する。2文字語だけは学習者が目にするものに絞ってある
- 評価は自力で達成したお題の数（5語以上 S / 4語 A / 2〜3語 B）

## やり込み

- **今日の盤 / 同じ盤をもう一度**: 並びが同じ盤を何度でもやり直せる。盤ごとに自己ベストが残る
- **検分**: 終局後、届かなかったお題ごとに「文字は全部来ていた（腕）」か「○ が来なかった（運）」かを示す
- **護符**: 1局に2つまで持ち込む道具。レベルで増える（★追加、NEXT 5枚、逆読みで成立、など）。`src/meta.ts`
- **碑文**: 盤上の技を見つけると刻まれる22枚。条件は伏せてあり、謎かけだけが読める
- **単語図鑑**: 盤面で作った受験語が層ごとに貯まる
- **復習**: つづりを見た・届かなかったお題は、あとの局に最大2語ずつ再登場する

## モード

共テ重点 / 難関2次重点 / 京大重点。お題に選ばれる語の層の確率が変わる（`src/core/words.ts` の `MODE_WEIGHTS`）。
層の定義は 共テ = CEFR A1〜B1、難関2次 = B2、京大 = C1〜C2。

## なぜこのルールか（シミュレーションの結果）

`npm run sim` は自動プレイでルールを測る。検討した3案の結果:

| 案 | 置けた文字 | お題の達成 | 判断 |
|---|---|---|---|
| 1枚ごとに必ず単語が要る（厳密） | 92〜98% | 0.05 / 6語 | 置くこと自体はできるが、6〜7文字の受験語がまず完成しない |
| 袋を引き切るまで続く「待ち」あり | 100% | 知っている語は全部 | 待ちが必ず報われるので運の要素がない |
| **手数制限つきの「待ち」あり（採用）** | 100% | 4.0 / 6語 | 待ちの成立率 83%。追うお題を選ぶ判断と文字運が両立する |

むずかしさ別の待ちの成立率は やさしい 91% / ふつう 83% / むずかしい 72%（お題を全部知っている自動プレイ、共テ重点、護符と手直しなし）。

## 開発

```sh
npm install
npm run dev       # 開発サーバー
npm test          # テスト
npm run build     # dist/ に静的ファイルを出力
npm run dict      # data/raw から辞書を再生成
npm run sim       # ルールのシミュレーション（引数: ゲーム数 モード）
npm run artifact  # CSS・JS・判定辞書を1枚にまとめた artifact/moji-xotol.html を作る
```

データの出典とライセンスは [data/SOURCES.md](data/SOURCES.md)。
